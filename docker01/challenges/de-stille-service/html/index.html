De stille service

Linux troubleshooting · APP-03

Situatie

De interne Inventory API op APP-03 is na een security-hardening niet meer bereikbaar vanaf andere servers.

Volgens systemd draait de service gewoon en volgens de applicatielog luistert deze op poort 9100.

Toch krijgt iedere verbinding vanaf het netwerk direct: Connection refused.

Netwerkgegevens

Systeem IP-adres Functie
APP-03 10.30.40.23 Inventory API
PROXY-01 10.30.40.10 Reverse proxy

Systemd-status

$ systemctl status inventory-api ● inventory-api.service Loaded: loaded (/etc/systemd/system/inventory-api.service) Active: active (running) Main PID: 1842 (python3) Tasks: 4 Memory: 41.2M

Applicatielog

$ journalctl -u inventory-api -n 5 Oct 12 08:14:02 APP-03 inventory-api[1842]: Application started Oct 12 08:14:02 APP-03 inventory-api[1842]: Listening on 0.0.0.0:9100

Controle op de host

$ ss -ltnp | grep 9100 $ curl http://127.0.0.1:9100/ curl: (7) Failed to connect to 127.0.0.1 port 9100: Connection refused $ curl http://10.30.40.23:9100/ curl: (7) Failed to connect to 10.30.40.23 port 9100: Connection refused

Opvallend: het proces draait wel, maar de host ziet de luisterende socket niet.

Service-unit

$ systemctl cat inventory-api [Unit] Description=Inventory API After=network.target [Service] Type=simple User=inventory Group=inventory ExecStart=/opt/inventory/venv/bin/python3 \ /opt/inventory/app.py Restart=on-failure PrivateTmp=yes NoNewPrivileges=yes ProtectSystem=strict PrivateNetwork=yes [Install] WantedBy=multi-user.target

Firewall

$ nft list ruleset | grep 9100 tcp dport 9100 accept
De firewallregel voor TCP/9100 is aanwezig. Het probleem ontstond direct na het toevoegen van extra systemd-hardening aan de service.

Opdracht

Welke systemd-instelling zorgt ervoor dat de service in een eigen netwerknamespace draait en daardoor niet bereikbaar is via het netwerk van de host?

Vul de directive in, bijvoorbeeld: Voorbeeld=yes
